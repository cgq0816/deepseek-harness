# 企业资源管理

使用本 Skill 管理企业连接器和技能中心中由用户或业务人员发布的 DSH 兼容 Skill。不要用它执行具体业务；已安装连接器的业务能力会以 `mcp__enterprise__*` 工具动态出现。

企业插件内置的基础能力（例如 `ocr-skill`）会自动注册，不通过本 Skill 搜索、安装或卸载。用户要求安装已经内置的能力时，说明它已随企业插件提供，并直接按对应业务 Skill 执行。

## 工具边界

- 只使用 `enterprise_connector_operation` 管理连接器。
- 只使用 `enterprise_skill_operation` 管理 Skill。
- 不使用 Shell、Python、浏览器脚本或本地文件读取企业 Token，也不直接拼接企业 API 请求。
- 如果工具提示尚未登录，引导用户先在「设置 → 企业」完成登录，不尝试绕过。

## 标准流程

1. 用户要浏览全部可用资源时使用 `action=list`。
2. 用户提供了名称、用途或关键词时先使用 `action=search`，并传入非空 `query`。
3. 展示搜索结果中的名称、说明、兼容性、版本和当前状态；不要猜测 ID 或版本。
4. 安装、升级、启停或卸载时，必须原样使用刚才结果中的 `connector_id` 或 `skill_id`。
5. 只有用户明确要求修改时才发起修改操作。工具会触发一次 DSH 用户审批；不要在审批前后重复索要同一确认。
6. 操作完成后根据工具返回的实际状态答复，不提前宣称成功。

## 连接器

`enterprise_connector_operation` 支持：

- `search`：按关键词搜索当前用户可见的连接器。
- `list`：列出可见连接器及安装、启用状态。
- `install`：绑定到当前用户在本机 DSH 的企业工作区。
- `enable` / `disable`：启用或停用已有绑定。
- `uninstall`：移除当前用户的本机绑定。

安装、启停或卸载后，插件会刷新统一企业 MCP。需要执行业务时，从刷新后的 `mcp__enterprise__*` 工具中选择匹配工具；每个连接器不会变成一个新的 MCP Server。

连接器搜索结果需要联合判断三个服务端状态：

- `runtime_compatible`：该版本的执行模式可由企业 Desktop Gateway 承载。
- `credential_ready`：租户管理员已在企业侧配置完整的共享凭证。
- `available_to_user`：企业部署已启用，且当前用户有权使用。

只有 `available_to_user=true`（兼容字段 `desktop_compatible=true`）时才允许安装。若 `credential_ready=false`，应说明需要租户管理员先在企业连接器中心完成“企业配置”，不得要求员工在 DSH 中输入 Key，也不得尝试把 Key 保存到本机。

## Skill

`enterprise_skill_operation` 支持：

- `search`：按关键词搜索当前用户可见、由用户或业务人员发布且 DSH 兼容的 Skill；不搜索企业内置 Skill。
- `list`：列出可见 Skill、版本和本机安装状态。
- `install`：安装或升级；可传搜索结果中的明确 `version`，省略则安装最新兼容版本。
- `uninstall`：仅卸载当前租户的企业受管副本。

安装成功后，业务 Skill 会立即加入 DSH Skill Catalog。后续任务匹配它时，按 DSH 原生规则加载该业务 Skill 的完整指令；不要把企业 Manager Skill 当作业务 Skill 使用。

### DSH 运行兼容性

搜索结果中的 `dsh_compatible` 只表示该发布包满足当前目录、名称和版本等基础准入条件，不等于其中每项能力都能在员工电脑直接运行。展示搜索结果时同时说明 `compatibility_reason`；不兼容时不得发起安装。

安装后首次用于实际任务时，先根据完整 `SKILL.md`、随包资源和工具引用判断运行类型，再按以下规则处理：

- 纯 Markdown/SOP：可直接使用。
- 只调用 DSH 当前已存在的动态 MCP 工具：加载 DSH 版 SOP；调用前确认所需工具确实出现在当前工具列表中。
- 包含本地脚本但不需要企业密钥：确认操作系统、命令和运行时依赖满足后再执行；缺少依赖时明确告知用户，不擅自安装系统软件。
- 依赖 RClaw 沙箱、专用 SDK、环境变量或企业 Token：只有包内明确提供 DSH Adapter 时才能使用；不得把企业登录 Token 或连接器密钥注入本地脚本。
- 只能在服务端执行：必须通过企业插件工具或远程 MCP 调用；不得尝试在本地复制服务端运行环境。

无法可靠归类、所需 Adapter 缺失或依赖声明不清楚时，停止执行该 Skill 的脚本部分并说明原因。不要因为“安装成功”就宣称“运行兼容”。兼容性判断只决定本地如何安全执行，服务端企业资源调用仍由 RClaw 每次重新鉴权。

## 失败处理

- 权限不足、资源不可见、不兼容、已下架或校验失败时，原样说明关键原因，不尝试本地伪造安装状态。
- 找到多个同名或相近资源时，先让用户依据说明、版本和 ID 选择。
- 动态业务工具尚未出现时，先重新列出连接器状态；已安装且启用仍不可用时，说明 MCP 刷新失败并建议重试，不虚构工具调用结果。
